Google OAuth 2.0 — installed-app (loopback) flow

The user grants exactly one scope: youtube.upload. The OAuth client is a Desktop app client, so the redirect is loopback only. Access is revocable at any time at myaccount.google.com/permissions.

YouTube Data API v3 — videos.insert (the only call)

part=snippet,status, resumable upload in 8 MiB chunks.
snippet: title, description (chapter timestamps derived from the user's own notes), tags, categoryId=20.
status: privacyStatus=unlisted (user-selectable), embeddable=true, selfDeclaredMadeForKids=false.
Cost: 1,600 quota units per upload. One at a time — never concurrent, never batched.

The user's own YouTube channel

The uploaded video, unlisted by default — theirs to edit or delete in YouTube Studio.

Not used and not requested

  • No backend. There is no server of ours in this diagram: the call is made from the user's own machine with the user's own credentials.
  • No read access. No search.list, no videos.list, no channel, comment, subscriber or analytics data is ever requested.
  • No third-party data. One user per installation, uploading their own recording. Nothing is uploaded without an explicit press of Upload.
